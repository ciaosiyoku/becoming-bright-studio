# Roadmap

The order follows the learning contract: the lesson first, then the parent page, then everything else.

## Version 1 (now)

| Step | Status |
|---|---|
| 1. Learning contract, with the session on paper | done |
| 2. Scaffold: Node 22, Vite, React, TypeScript, Vitest; Home, Lesson, Parent; one IndexedDB key; backup file with a weekly reminder | done |
| 3. Three-step skill: teach card, 2 guided tries, 5 checks (4 of 5 = mastered); skills in JSON; nothing moves on by itself | done |
| 4. Twelve skills, numbers made in code, "exactly one right answer" test in every language | done |
| 5. Parent control: salted-hash PIN, recovery code printed once, no 24-hour reset, backup as recovery, one parent screen with today's misses and "games allowed" | done |
| 6. Several children, each with their own progress; family PIN | done |
| 7. Test with one 6-year-old ([docs/CHILD-TEST.md](docs/CHILD-TEST.md)) | **to do: needs a child** |
| 8. PWA that says what it is; install page without lock claims | done |
| 9. Languages: German, French and Yoruba released by the owner's decision | **to do: native speakers to read every child-facing sentence aloud** |
| 10. Reward: a 5-minute memory game made of the skill's own questions, only when games are allowed | done |

## Next, in this order

1. **The child test** (step 7). Change the teach card or the feedback for what it shows, then test again.
2. **Native-speaker readings** of German, French and Yoruba, sentence by sentence (app text and skill texts).
3. **Real devices:** an Android or Fire tablet and an iPad: install, read-aloud voices, print, file backup.
4. More skills only after the first twelve work with children (e.g. number bonds to 10, halves, CVC words).

## Later, as separate decisions

- Video only from files we host, or a source whose terms allow a children's app. Never embedded YouTube in the
  first public version.
- A native app for a bedtime lock: a different product, not a setting in this one.
